# Prompting Gemini 3.5 Flash for Exhaustive Character Extraction — Research Report (Juli 2026)

> Recherche-Bericht (Stand 2026-07-11). Offizielle Google-Doku priorisiert; Best-Practice-Artikel als **[non-official]** gekennzeichnet.

## Scope-Hinweis zum Modell

**"Gemini 3.5 Flash" ist ein reales, dokumentiertes Modell** — keine Extrapolation aus 2.5/2.0 nötig. Offizielle Seite: [What's new in Gemini 3.5 Flash](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.5). Wo auf 2.5-Ära-Forschung gestützt wird (lost-in-the-middle, GraphRAG gleaning), ist das explizit markiert.

---

## TL;DR — das hier tun (Top 7)

1. **NICHT das ganze Buch in einem Call und exhaustive Listen erwarten.** Googles Long-Context-Doku warnt: Multi-Item- ("multiple needles") Retrieval ist deutlich ungenauer als Single-Needle. Buch chunken, pro Chunk extrahieren, mergen. **[official]**
2. **Gleaning-Pass pro Chunk:** nach der ersten Extraktion "Welche Charaktere hast du übersehen?" nachschieben. Best belegter Recall-Booster (GraphRAG). **[research]**
3. **Natives Structured Output (`response_format` + JSON-Schema)**, nicht Prompt-eingebettete JSON-Anweisung; mit Pydantic/Zod validieren — schema-valide ≠ semantisch vollständig. **[official]**
4. **Charakterliste als Top-Level-Array von Objekten** mit reichen Per-Entity-Feldern via Schema-`description`; Schema nicht im Prompt wiederholen. **[official]**
5. **Silent Truncation abfangen:** lange Listen können das 65k-Output-Limit sprengen → abgeschnittenes (invalides) JSON. `finish_reason` prüfen, Output pro Call begrenzen, Beschreibungen kappen. **[official + best-practice]**
6. **Gemini 3.x anders prompten als 2.x:** knapp & direkt, `temperature`/`top_p`/`top_k` entfernen, `thinking_level` nutzen (Default `medium`; `high` für die schwersten Pässe). Verbose "alte" Prompt-Technik kann schaden. **[official]**
7. **Jeden Charakter an Quelltext binden** (Quote/Offset) und **Spoiler-Cutoff hart am Input** (nur Text bis Checkpoint senden). Googles LangExtract groundet jede Extraktion an Source-Offsets. **[official]**

## 1. Recall / Vollständigkeit — Nebenfiguren nicht verlieren

**Zentrale offizielle Erkenntnis (load-bearing für unser Problem):** Gemini erreicht ~99 % bei *Single*-Needle-Retrieval, aber *"In cases where you might have multiple 'needles'… the model does not perform with the same accuracy."* Für garantierten Multi-Item-Recall wird empfohlen, in mehrere Requests zu splitten. Exhaustive Charakter-Extraktion **ist** Multi-Needle → Ganzbuch-Single-Shot ist genau der degradierende Fall.
Quelle: [Long context — Gemini API](https://ai.google.dev/gemini-api/docs/long-context) **[official]**

**Gleaning / "did you miss any?" Multi-Pass** — best belegt. In GraphRAG wird nach der ersten Extraktion nach übersehenen Entitäten "gegleant", weil *"the first LLM extraction is typically not exhaustive."* Gleiches Paper: Modelle extrahieren **~2× mehr Entitäten aus 600-Token-Chunks als aus 2400-Token-Chunks** — kleinere Chunks heben den Recall direkt.
Quelle: [From Local to Global: A Graph RAG Approach (arXiv 2404.16130)](https://arxiv.org/pdf/2404.16130) **[research, 2024]**

**Googles eigene Produkt-Antwort ist LangExtract** — Gemini-gestützte Extraktions-Library, Recall-Strategie wörtlich: *"a chunking strategy, parallel processing and multiple extraction passes over smaller, focused contexts."* Google endorsed chunk + parallel + multi-pass für Long-Doc-Extraktion. (Quickstart nutzt `gemini-2.5-pro`, Technik ist modell-agnostisch.)
Quelle: [Introducing LangExtract (Google Developers Blog)](https://developers.googleblog.com/en/introducing-langextract-a-gemini-powered-information-extraction-library/) **[official]**

**Konkrete Recall-Taktiken kombinieren:**
- **Buch chunken** (pro Kapitel oder ~2–4k-Token-Fenster), pro Chunk extrahieren; klein genug, dass Nebenfiguren nicht begraben werden.
- **Gleaning-Pass** pro Chunk: Chunk + bereits gefundene Namen zurückgeben, nur *zusätzliche* Charaktere anfragen.
- **Merge + Dedupe** über Chunks (Alias-Auflösung: "Bob" / "Robert" / "Mr. Smith").
- **Explizite Exhaustiv-Anweisung** ("Include every named or clearly-identified character, including minor and one-scene characters; do not omit anyone who is named or speaks."). Das Cookbook-Beispiel verlangt Vollständigkeit *nicht* in Worten und verlässt sich aufs Schema — Anweisung selbst hinzufügen; ist billig. [Cookbook: Entity_Extraction_JSON.ipynb](https://github.com/google-gemini/cookbook/blob/main/examples/json_capabilities/Entity_Extraction_JSON.ipynb) **[official]**
- **Few-shot-Beispiel** mit einer erfassten Neben-/Einzeilfigur — Googles Guide: *"We recommend to always include few-shot examples… Prompts without few-shot examples are likely to be less effective."* [Prompt design strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies) **[official]**
- **Mindestanzahl / Coverage-Checklist:** **keine** offizielle Basis für "extract at least N". Kann helfen, riskiert aber halluziniertes Padding; als weiche Heuristik behandeln, keine Garantie. **[unverified / mit Vorsicht]**

## 2. Long-Context-Handling — echte Zahlen

**Kontextfenster: 1.048.576 Input-Tokens (1M). Max Output: 65.536 Tokens (64k).** Unterstützt Thinking und den vollen Gemini-3-Tool-/Plattform-Featureset.
- Primäre offizielle Bestätigung ("1M token context window, 65k max output tokens"): [What's new in Gemini 3.5 Flash](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.5) **[official]**
- Die exakten Integer 1.048.576 / 65.536 sind Standard-Spec-Werte, über Aggregatoren korroboriert (z. B. [OpenRouter](https://openrouter.ai/google/gemini-3.5-flash), [llm-stats](https://llm-stats.com/models/gemini-3.5-flash)). **[secondary]** — die numerische Tabelle war von der offiziellen [Models-Seite](https://ai.google.dev/gemini-api/docs/models) nicht direkt extrahierbar; bei Byte-Genauigkeit die Per-Model-Spec-Seite gegenprüfen.

**Best Practices (official):**
- **Instruktion/Frage ans Ende, nach dem Dokument.** *"Place your specific instructions or questions at the end of the prompt, after the data context."* [Long context](https://ai.google.dev/gemini-api/docs/long-context), [Gemini 3 Developer Guide](https://ai.google.dev/gemini-api/docs/gemini-3) **[official]**
- **Ganzbuch vs. chunked:** Ganzbuch okay für *Summarization/Q&A*, nicht für exhaustive Multi-Entity-Extraktion (siehe §1). Für Coverage chunken.
- **"Lost in the middle":** klassische U-Form (hoher Recall an Start/Ende, Durchhänger in der Mitte) breit dokumentiert; 2.5-Ära-Tests deuten robustes *Single*-Needle-Factoid-Recall unabhängig von Position an — gilt **nicht** für Multi-Entity, per Googles Multi-Needle-Caveat. **[research — 2404/2407 arXiv; Single-Needle-Robustheit versions-spezifisch]**
- **Context Caching** für den geteilten Buchtext über Pässe/Gleaning senkt Kosten: *"If you have a similar set of tokens / context that you want to re-use many times, context caching can help reduce the costs."* [Long context](https://ai.google.dev/gemini-api/docs/long-context) **[official]** — relevant, da Multi-Pass dasselbe Kapitel re-sendet.

## 3. Structured Output — verlässliches JSON

**Natives Structured Output** statt "return JSON" im Prompt. Bei Gemini 3.x JSON-Schema via `response_format` (`mime_type: application/json` + `schema`); Pydantic `.model_json_schema()` oder Zod `z.fromJSONSchema()` sind die gezeigten Idiome. [Structured outputs](https://ai.google.dev/gemini-api/docs/structured-output) **[official]**

**Offizielle Best Practices (zitiert):**
- *"Use the `description` field to guide the model."* → Per-Charakter-Guidance (was zählt als Charakter, wie lang die Beschreibung) in Schema-`description`s.
- *"Use specific types (integer, string, enum)."*
- *"While output is syntactically correct JSON, always validate values in your application."*
- *"Implement robust error handling for schema-compliant but semantically incorrect outputs."*

**Offizielle Limitierungen (zitiert):**
- *"Not all JSON Schema features are supported."*
- *"Very large or deeply nested schemas may be rejected."* → Charakter-Schema flach halten (flaches Array von Objekten), nicht tief verschachtelt.

**[non-official, aber konsistent]** Googles Nov-2025-Blog kündigte **JSON-Schema-Support und *implizites* Property-Ordering** an — der alte `propertyOrdering`-Workaround (2.0 Flash) wird auf 2.5/3.x automatisch gehandhabt. [Improving Structured Outputs in the Gemini API (blog.google, 5. Nov 2025)](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-structured-outputs/) **[official blog]**. Ergänzende Artikel: Schema nicht im Prompt duplizieren (kann Qualität *senken*), nicht unterstützte Schema-Keywords werden *stillschweigend ignoriert* — reales Schema end-to-end testen. [oneuptime](https://oneuptime.com/blog/post/2026-02-17-how-to-use-gemini-structured-output-and-json-mode-for-reliable-data-extraction/view), [crazyrouter](https://crazyrouter.com/en/blog/ai-structured-output-json-mode-guide-2026) **[best-practice, unverified]**.

**Truncation-Gotcha (wichtig für lange Listen):** ein exhaustives Charakter-Array kann das **65k-Output-Cap** treffen und als *abgeschnittenes, unparsebares* JSON-Array zurückkommen. Mitigation: `finish_reason` / `MAX_TOKENS` prüfen, Beschreibungslänge im Schema begrenzen, pro Chunk extrahieren (kleinere Arrays), downstream mergen. Offizielle Seite schweigt dazu → **muss getestet werden**. **[best-practice-Konsens; offizielle Doku still — flagged]**

**Schema-Design ↔ Vollständigkeit:** ein einzelnes Top-Level-`characters: [ {name, aliases, role, description, first_appearance_quote} ]`-Array ist die richtige Form. Rekursive/`$ref`-Verschachtelung meiden. Weniger, flachere Felder = weniger Per-Item-Token-Kosten = mehr Charaktere vor dem Output-Cap.

## 4. Detail / Reichhaltigkeit pro Entität ohne Halluzination

- **An Quelltext binden.** LangExtracts Headline-Feature: *"Every extracted entity is mapped back to its exact character offsets in the source text."* Pattern übernehmen — kurzes wörtliches `quote` (oder Anchor-Snippet) pro Charakter verlangen. Curbt Halluzination + liefert den Anker für KOReader. [LangExtract blog](https://developers.googleblog.com/en/introducing-langextract-a-gemini-powered-information-extraction-library/) **[official]**
- **Tiefe via Schema-description + explizite Längenlimits.** Google: *"Specify any constraints… you can tell the model exactly how long a summary should be."* "≤ 200 Zeichen, nur im Text genannte Fakten" in die Feld-`description`. [Prompt design strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies) **[official]**
- **Anti-Halluzinations-Anweisung:** "Only include information stated or directly implied in the provided text. If a character's role is unknown, leave the field empty — do not guess." Mit Pflicht-`quote`-Feld paaren.
- **Few-shot für konsistente Tiefe:** ein Beispiel-Objekt mit exakt der gewünschten Reichhaltigkeit/Länge, konsistentes Format (Guide betont identische Struktur/Whitespace über Beispiele). **[official]**

## 5. Spoiler-Safety (D4 im Design)

**Robuste Kontrolle ist Input-Truncation, nicht Prompting.** Nur Text bis zum Checkpoint senden; dann kann selbst ein voll-konformes Modell keine späteren Events leaken. Prompt-Level "erwähne nichts nach Kapitel N" ist weicher Guard, sekundär. Unsere Chunk-und-Checkpoint-Architektur ermöglicht das bereits — harter Cutoff auf Input-Layer. Pflicht-`quote` pro Charakter erlaubt zusätzlich zu prüfen, dass kein Quote von jenseits des Checkpoints stammt. **[abgeleitet aus offizieller Grounding-Praxis + Design; "Input truncaten" ist kein Gemini-spezifischer Doc-Claim]**

## 6. Gemini-3.x-spezifische Gotchas vs. 1.5 / 2.0 / 2.5

Alle **[official]**, aus [What's new in Gemini 3.5 Flash](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.5) und [Gemini 3 Developer Guide](https://ai.google.dev/gemini-api/docs/gemini-3):

- **`temperature`, `top_p`, `top_k` entfernen.** *"`temperature`, `top_p`, and `top_k` are no longer recommended for all Gemini 3.x models… Remove these parameters from all requests."* Default temp 1.0; Absenken für "Determinismus" kann *Looping / Degradation* verursachen. Für Determinismus stattdessen *"define a system instruction with explicit rules."* → **Temperatur-Tuning aus 2.5/1.5-Config löschen.**
- **`thinking_budget` → `thinking_level`** (Enum `minimal | low | medium | high`). Default **`medium`** (war `high` in 3-Flash-preview). Für die härtesten Exhaustiv-/Merge-Pässe `high`; für billige mechanische Pässe `low`/`minimal`.
- **Prompt-Stil invertiert vs. ältere Modelle.** *"Be concise… Gemini 3 responds best to direct, clear instructions,"* und es *"may over-analyze verbose or overly complex prompt engineering techniques used for older models."* → **Elaborierte Multi-Absatz-Steuerung strippen.**
- **Weniger verbose per Default** — chattigere Beschreibungen explizit anfragen.
- **Function-Call-Migration** (nur bei Tools): `FunctionResponse`-Parts brauchen matchende `id`/`name`; Thought-Preservation default an (kann Token-Usage erhöhen).

## Copy-worthy Prompt- / Schema-Patterns

**Per-Chunk-Extraktion (System-Instruktion, knapp — 3.x-Stil):**
```
Extract EVERY character that is named or clearly identified in the text below,
including minor, secondary, and single-scene characters. Do not omit anyone.
Use only information stated or directly implied in the text. If a field is
unknown, leave it empty — never guess. Text is only part of a book; extract
only what appears here.
[Few-shot example object showing a one-line minor character captured]
--- TEXT ---
{chunk}
```
(Instruktion und Text am Ende, per offizieller Placement-Guidance.)

**Gleaning-Pass:**
```
Here is the same text and the characters already found: {names}.
List ONLY additional characters not in that list. If none, return an empty array.
```

**Schema-Shape (flach, description-geführt):**
```json
{"type":"object","properties":{"characters":{"type":"array","items":{
 "type":"object","properties":{
  "name":{"type":"string","description":"Primary name as it appears in the text"},
  "aliases":{"type":"array","items":{"type":"string"}},
  "role":{"type":"string","description":"1-4 words, e.g. 'protagonist','servant'. Empty if unclear."},
  "description":{"type":"string","description":"<=200 chars, only facts from the text"},
  "quote":{"type":"string","description":"Short verbatim snippet from the text where the character appears"}
 },"required":["name","description","quote"]}}},"required":["characters"]}
```

## Ehrliches Unsicherheits-Ledger

- **Exakte Token-Zahlen (1.048.576 / 65.536):** offizielle Seite bestätigt "1M / 65k" in Prosa; exakte Integer aus Spec-Aggregatoren, nicht byte-verifiziert. **Bei Präzisionsbedarf Per-Model-Spec-Seite prüfen.**
- **Output-Truncation-Verhalten von Structured Output:** offizielle Doku still; "truncated array = invalid JSON, check finish_reason" ist Best-Practice-Konsens, kein Google-Statement. **Testen.**
- **"Mindestanzahl" erzwingen und "Coverage-Checklist":** kein offizieller Support gefunden; plausibel, aber Risiko halluzinierten Paddings. **Als Heuristik behandeln.**
- **Single-Needle-Positions-Robustheit von Flash:** aus 2.5-Ära-Tests/Blogs; nicht auf Multi-Entity-Recall übertragen — Googles Multi-Needle-Caveat sagt, es transferiert nicht.
- **LangExtract-Default-Modell** ist `gemini-2.5-pro` im Quickstart, nicht 3.5 Flash — endorsed ist die *Technik* (chunk/parallel/multi-pass/grounding), nicht das spezifische Modell-Pairing.
